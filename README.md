# น้ำถึงไหน

เว็บเฝ้าระวังสถานการณ์น้ำรายอำเภอและตำบล ลุ่มยม น่าน เจ้าพระยา (10 จังหวัด) ดึงข้อมูลจาก ThaiWater (สสน.) อัตโนมัติทุก 30 นาที

## การทำงาน

```
ทุก 30 นาที  netlify/functions/fetch-scheduled.mjs
  → ดึง ThaiWater (lib/ingest.mjs)
  → ตรวจรูปแบบข้อมูล / จำนวนสถานี (ถ้าผิดปกติ เก็บข้อมูลรอบก่อนไว้ และแจ้งว่าดึงไม่สำเร็จ)
  → ดึงฝนสะสม 3 วัน / 7 วัน ราย 10 จังหวัด (lib/rain.mjs, API เดียวกับศูนย์ข้อมูลน้ำระดับจังหวัด)
  → รวมสถานีต่างหน่วยงานที่ตั้งจุดเดียวกัน (ห่างกันไม่เกิน ~300 ม.) ให้นับครั้งเดียว
  → คำนวณสถานะ แนวโน้ม 6 ชม. และสรุปรายจังหวัด (lib/analyze.mjs)
  → (ถ้าตั้งค่า AI) ให้ AI เรียบเรียงเฉพาะจังหวัดที่สถานการณ์เปลี่ยน (lib/ai.mjs)
  → บันทึกลง Netlify Blobs: data/latest, data/history

/api/latest   ข้อมูลล่าสุดสำหรับหน้าเว็บ (cache 1–2 นาที)
/api/refresh  สั่งดึงทันที (ห่างกันอย่างน้อย 5 นาที)
/api/probe    ทดสอบการเข้าถึงแหล่งข้อมูลทั้ง 3 แหล่ง (หน้า /status.html)
```

## เกณฑ์สถานะ

| สถานะ | เงื่อนไข |
|---|---|
| ล้นตลิ่ง | ระดับน้ำสูงกว่าตลิ่ง หรือ % ความจุ > 100 |
| เฝ้าระวัง | % ความจุ ≥ 80 |
| ปกติ | % ความจุ < 80 |
| ข้อมูลเก่า | สถานีไม่ส่งข้อมูลเกิน 3 ชม. (ไม่นำมาคิดสถานะ) |

แก้เกณฑ์ จังหวัด สถานีหลัก ผังแม่น้ำ และประกาศทางการได้ที่ `lib/config.mjs` ไฟล์เดียว

## อัปเดตโค้ดขึ้น GitHub

**อัปโหลดทุกไฟล์ใน commit เดียว** เพราะแต่ละ commit = 1 production deploy = 15 เครดิต Netlify

1. เปิด repo บน GitHub → **Add file → Upload files**
2. ลากทุกอย่างในโฟลเดอร์นี้ (`lib`, `netlify`, `public`, `netlify.toml`, `package.json`, `package-lock.json`, `README.md`) ไปวางพร้อมกัน ไฟล์ชื่อเดิมจะถูกแทนที่
3. กด **Commit changes** ครั้งเดียว

## หลัง deploy

1. เปิด `https://<ชื่อเว็บ>.netlify.app/api/refresh` หนึ่งครั้ง เพื่อดึงข้อมูลรอบแรกทันที (ไม่ต้องรอ 30 นาที)
2. เปิดหน้าแรก ควรเห็นเวลาข้อมูลล่าสุด และสรุปรายจังหวัด
3. หลัง 1 ชม. ตรวจ Netlify → Logs → Functions → `fetch-scheduled` ว่ารันทุก 30 นาที

## เปิดใช้ AI เรียบเรียงข้อความ (ไม่บังคับ)

Netlify → Project configuration → Environment variables → **Add a variable → Import from a .env file** แล้ววาง (ใส่เฉพาะบรรทัดที่มี key):

```
GEMINI_API_KEY_1=ใส่คีย์
GEMINI_API_KEY_2=ใส่คีย์
GEMINI_API_KEY_3=ใส่คีย์
GROQ_API_KEY=ใส่คีย์
CLAUDE_API_KEY=ใส่คีย์
```

- Scopes: เลือก **Functions** (หรือ All scopes) · Deploy contexts: **Production** (หรือ All)
- ค่า Environment variables มีผลหลัง deploy ครั้งถัดไป → ตั้งค่าก่อนอัปโหลดโค้ด จะได้ไม่ต้อง deploy เพิ่ม
- ลำดับที่ระบบลอง: Gemini #1 → #2 → #3 → Groq → Claude (เปลี่ยนได้ด้วย `AI_ORDER=gemini,claude,groq`)
- ไม่บังคับ: `GEMINI_MODEL` (ถ้าไม่ใส่ ระบบเลือก Gemini Flash รุ่นที่ key ใช้ได้เอง), `GROQ_MODEL` (ค่าเริ่มต้น llama-3.3-70b-versatile), `CLAUDE_MODEL` (ค่าเริ่มต้น claude-haiku-4-5-20251001)
- ตรวจว่า key ไหนใช้ได้: เปิด /status.html → กด **ตรวจ AI** (ไม่แสดง key)
- ห้ามใส่ key ในไฟล์ใด ๆ ใน GitHub

กติกา AI ในระบบนี้
- เรียบเรียงเฉพาะจังหวัดที่สถานการณ์เปลี่ยน สูงสุด 3 จังหวัดต่อรอบ ข้ามถ้ารอบนั้นดึงข้อมูลนานเกิน 15 วินาที
- key ที่โควตาเต็มหรือใช้ไม่ได้ ระบบข้ามไปตัวถัดไปทันที
- ตัวเลขและระดับความเสี่ยงมาจากกฎตายตัวเสมอ ถ้า AI ใส่ตัวเลขที่ไม่มีในข้อมูล ระบบทิ้งข้อความนั้นแล้วลองตัวถัดไป หรือใช้ข้อความแบบกฎแทน
- หน้าเว็บบอกเสมอว่าข้อความไหน AI (เจ้าไหน) เรียบเรียง

## เปลี่ยนแปลง v5

- พยากรณ์ฝน 4 วัน (วันนี้ + 3 วัน) บริเวณตัวจังหวัด จาก Open-Meteo (แบบจำลอง, ดึงทุก 3 ชม., เรียกครั้งเดียวได้ 10 จังหวัด) แสดงระดับฝนตามเกณฑ์กรมอุตุฯ และพูดถึงในข้อความสรุปเมื่อ ≥ 10.1 มม./วัน
- AI หลายเจ้า: Gemini (สูงสุด 3 key หมุนเมื่อโควตาเต็ม) → Groq → Claude, ตรวจตัวเลขก่อนใช้, จำกัดเวลาให้อยู่ในกรอบ 30 วินาที
- /api/ai-check + ปุ่ม "ตรวจ AI" ใน /status.html บอกว่า key ไหนใช้ได้ โควตาเต็ม หรือเครดิตหมด

## เปลี่ยนแปลง v4

- เพิ่มข้อมูลกรมชลประทานจาก bigdata-swoc.rid.go.th (สถานีน้ำท่า มีปริมาณน้ำ ลบ.ม./วินาที, % ความจุลำน้ำ, เทียบเมื่อวาน) รวมกับ ThaiWater: สถานีรหัสเดียวกันเติมปริมาณน้ำ สถานีที่ ThaiWater ไม่มีเพิ่มเข้าไป
- เพิ่มข้อมูลเขื่อนต้นน้ำรายวันจาก app.rid.go.th/reservoir (% น้ำในอ่าง ไหลเข้า ระบาย)
- ถ้า Netlify เข้าเว็บกรมชลฯ ไม่ได้ ระบบข้ามไปใช้ ThaiWater อย่างเดียว และหน้าเว็บบอกสถานะการเชื่อมต่อ
- /api/probe และ /status.html ทดสอบ 2 แหล่งใหม่ด้วย

## เปลี่ยนแปลง v3

- เพิ่มฝนสะสม 3 วัน / 7 วัน รายจังหวัด (5 สถานีสูงสุด) และข้อความเตือนเมื่อฝน 3 วัน ≥ 100 มม. (เกณฑ์ของระบบ ไม่ใช่เกณฑ์ทางการ)
- รวมสถานีที่ตั้งจุดเดียวกัน เช่น C.36 กับคลองบางหลวง ไม่นับจุดล้นตลิ่งซ้ำ
- ไม่ใช้ข้อมูลพื้นที่ประสบภัยจาก proxy ของเว็บจังหวัด เพราะเป็นช่องทางที่ใช้บัญชีของหน่วยงานอื่น

## ข้อจำกัดตอนนี้

- กรมชลประทาน และสำนักการระบายน้ำ กทม. บล็อกการเชื่อมต่อจากเซิร์ฟเวอร์ต่างประเทศ (Netlify อยู่ us-east-2) จึงยังไม่มีปริมาณน้ำ (ลบ.ม./วินาที) และคลอง 304 จุดของ สนน. ต้องเพิ่มตัวดึงข้อมูลที่รันในไทยภายหลัง
- เวลาน้ำเดินทางมีเฉพาะลุ่มเจ้าพระยา
- ข้อมูลเป็นของ สสน. กรมชลประทาน และ สนน. ก่อนเปิดใช้สาธารณะควรขออนุญาตใช้ข้อมูล
